This is a [published release](https://github.com/googleapis/release-please/releases/tag/v17.11.2), rather than unreleased repository source. ## Adoption gate

`.release-please-manifest.json` preserves the merged JS/private-types/Rust 2.0.0 entries and proposes adding Elixir's truthful 1.0.1 management seed; `bootstrap-sha` remains the approved full shared boundary. Generation is enabled through PR #71. JS/npm and Rust/crates.io publication remain enabled by policy. Elixir's generation-only adoption and maintainer-confirmed Hex setup are described in the [dated activation record](sdk-release-adoption.md#elixir-generation-activation-2026-11-06); its registry publisher remains disabled. `SDK_RELEASES_ENABLED=true` is required for execution. No fallback initial version or unbounded history is used.

Management requires accepted source/registry evidence, distinct full `adoptionSourceRevision`, reviewed pre-major `manifestVersion`, and a deliberately selected full ancestor boundary shared with `bootstrap-sha`. Known native historical source SHAs remain separate; npm can retain unknown original provenance only after explicit `artifactComparisonAccepted` and `historicalSourceUncertaintyAccepted`. JS additionally requires its public-type migration review and confirmed license. Publisher enablement additionally requires accepted ownership, exact trust and hosted preflight evidence. Do not mark reported setup as observed authentication or require a prior successful publication for the first upload.

Manage only evidence-ready groups. Configuration, linked plugin and manifest membership must exactly match `release.managed`; JS/types must align, private types never publish, and unresolved unmanaged Elixir does not block JS/Rust. Initial proposed versions must strictly advance their seeds to exactly 2.0.0; subsequent versions must remain stable and in the exact configured major. An approved tag must match both its source package and management manifest. See [the staged checklist](sdk-release-adoption.md).

`node scripts/releases/check-release-config.cjs --require-ready` validates the current generation and publishing policy separately from the repository execution switch. The [publisher-activation record](sdk-release-adoption.md#publisher-activation-2026-11-05) attributes ownership and trust to maintainer confirmation and preserves the successful hosted preflight and App-created PR checks. Runtime registry authentication and publication remain unobserved until an approved release merge completes its fresh verification and upload.

## Major-2 adoption evidence (2026-11-02)

All three stable versions and archive SHA256 values above remain unchanged. npm 1.0.3 has no deprecation marker or `gitHead`; Hex 1.0.1 has no retirement record; Rust 1.0.0 is not yanked. npm's five bundled sourcemap sources exactly match both `eb15bb1fd7e59e889f501dd5334c65c670562d55` and `fd5f8c864c11c9ef7bbd447cc9ace17678844319`, which demonstrates artifact/source correspondence but cannot identify the exact publication commit. The Hex archive's six library/manifest files exactly match the historical source commit already recorded. The Rust archive again identifies its historical SHA and subdirectory in `.cargo_vcs_info.json`.

Historical source, reviewed adoption source, fixed history boundary, management seed and desired first version are separate fields. JS/private types are aligned to seed 1.0.3; Rust preserves unpublished local 1.0.1. `firstReleaseTarget` is exactly 2.0.0 for each initial SDK, never an invented published version. On 2026-11-02 the maintainer accepted reviewed source `9bd974df2efe1693b142fed184c42785565119d7` and fixed history boundary `8b4d80c05abec38d953f38b6bf59ff96462939fa`, including artifact-based npm provenance uncertainty and unpublished Rust 1.0.1. JS/types and Rust are managed with exact config/plugin/manifest membership and truthful pre-major seeds; Elixir remains unmanaged. At this historical preparation stage, generation-only policy was prepared and every publisher remained disabled. [The adoption record](sdk-release-adoption.md) records subsequent hosted readiness and the dated publisher-activation evidence separately.

The pinned generator fixtures prove first 2.0.0 proposals for JS/types, Rust and delayed Elixir from representative truthful 1.x seeds, native manifest/changelog/Cargo lock updates, then patch 2.0.1 from committed first-target state. Separate fixtures preserve delayed Elixir history without advancing the shared boundary, and reject a stale first target after a coordinated major change. These synthetic tests establish generator behavior, not accepted production source history or hosted authentication.
